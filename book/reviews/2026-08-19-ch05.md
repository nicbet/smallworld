## 1. Design inconsistencies (listing vs. prose vs. spec)

### 1.1 `push_map`/`pop_map` live in three incompatible places (highest priority)

- `@lst-action-queries` puts `fn push_map(&mut self, ...)` / `fn pop_map(&mut self)` on `impl Input`, matching the spec.
- The "Input in the GameContext" section says the opposite: "the engine routes stack operations through a dedicated method on `GameContext` rather than through the immutable `input` borrow."
- `@lst-game-context` shows no such methods, and `GameContext.input` is `&'a Input`, so the `&mut self` methods on `Input` are unreachable from game code.

The prose's answer (methods on `GameContext`, backed by engine state) is the right design and matches the spec's existing pattern for registration/game-flow methods. Fix: move the two methods out of `@lst-action-queries` into the `GameContext` impl (or mention them there), and update `docs/architecture/describing-a-game.md` §5 to match. **Spec edit needs a decision** since the spec currently agrees with the listing, not the prose.

### 1.2 `fixed_action_pressed(&self)` contradicts the chapter's own immutability claim

The Raw Polling API section states: "no query can trigger a side effect or modify the snapshot." Two sections later, `fixed_action_pressed` is defined as a consumed-once latch that "clears it on first consumption," through `&self`. Both cannot be true as written. Options: (a) scope the no-side-effect claim to raw device queries and explicitly carve out the fixed-tick latches (with a sentence on interior mutability), or (b) respecify the latch as cleared at fixed-tick boundaries rather than on read. The spec shares the `&self` signature, so whichever wording lands should be reflected there.

### 1.3 Controller storage: three artifacts of the array-to-Vec refactor collide

1. The quarantine listing does `if let Some(c) = &mut input.controllers[id]`, which requires `Vec<Option<ControllerState>>`; `@lst-input-struct` and the spec declare `Vec<ControllerState>`. Minimal fix: `input.controllers.get_mut(id)`.
2. The "What You Will Learn" bullet still says "the fixed-size controller array"; the chapter now argues for and uses a dynamic `Vec`. Stale.
3. §Multiple Controllers claims both that the quarantine "populates this vector from the OS device list each frame" / "the `Vec` is allocated once per frame" AND that "slot indices are stable within a session." A `Vec` rebuilt per frame cannot keep indices stable across a mid-session disconnect (removal shifts later entries). Also, per-frame allocation is a needless steady-state allocation (perf-first). Coherent story: the vector is retained and updated in place on connect/disconnect events; either keep tombstone slots for index stability or drop the index-stability claim and lean fully on `ControllerId` identity (which the section already argues is the real mechanism).

### 1.4 Controller button edges are never computed

The quarantine rotates `keyboard.previous` and `mouse.prev_buttons` and calls `keyboard.compute_edges()`, but `ControllerState` has no previous-frame state and the listing never rotates controller buttons. `action_pressed` on a `ControllerButton` binding requires those edges. Either add previous-state/edge computation for controllers (listing comment suffices) or note where it happens.

### 1.5 `ControllerAxis { axis: u8 }` cannot feed an `Axis2d` action as written

The "move" example binds `Axis2d` to `ControllerAxis { device: Any, axis: 0, dead_zone: 0.15 }`, but a single axis index names one scalar HID axis; a stick is two. The HOTAS discussion uses the same binding for genuine 1D axes, so the field is overloaded. Related: the prose describes the dead zone as "the radius below which the axis reports zero," which is a radial (2D) concept that a per-scalar-axis dead zone cannot implement; per-axis dead zones produce the well-known axial-snapping artifact. The spec has the same shape, so this is a **spec-level ambiguity to resolve**: e.g., add a `ControllerStick`-style binding (two axes, radial dead zone) alongside scalar `ControllerAxis`, or define `axis` as indexing predefined 2D groups for `Axis2d` actions.

### 1.6 Multi-binding resolution rule is two rules

"The engine returns the most recent non-zero contributor (with analog sources taking priority over digital composites when both are active)" states two policies that can conflict, and "most recent" is undefined within a single snapshot (it requires cross-frame actuation tracking). Pick one deterministic rule and state it, e.g. largest-magnitude wins, or last-actuated device wins with analog priority as the tie-break.

### 1.7 `update`/`fixed_update` signatures do not match the spec's `App` trait

`@lst-intent-pattern` shows `fn update(&mut self, ctx: &GameContext)` and `fn fixed_update(&mut self, ctx: &mut GameContext)`. The spec's trait is `fn update(&mut self, ctx: &mut GameContext, dt: f32)` and `fn fixed_update(&mut self, ctx: &mut GameContext, fixed_dt: f32)`. This is the book's first appearance of these hooks, so whatever chapter formally introduces `App` will collide. Align now (unused params can be `_dt`).

### 1.8 Smaller inconsistencies

- `@lst-action-types` field comment reads `// Button | Axis1d | Axis2d`, omitting `Axis3d` (the enum below and the spec both have four variants).
- Glyph return type: one paragraph says `glyph()` "returns a `GlyphId` that the UI resolves to the appropriate icon asset"; the next says the caller "receives an asset handle." Pick one (GlyphId, per the listing).
- `DeviceTracker` hysteresis: prose promises "two to three consecutive **frames**"; the listing counts calls to `update()`. If `update` runs per event during the drain, several events in one frame commit the switch within a single frame. Specify the cadence (once per frame with that frame's dominant source).
- Wrong cross-reference: "raw device queries (the same methods introduced in @sec-platform-events)" — the raw polling API was introduced under @sec-device-to-intent.

## 2. Factual checks

Verified correct: Elden Ring PC launch 2022; Dark Souls PC port a decade earlier; Joy-Con drift class action and free repair program; CVAA enforcement beginning 2019; Xbox Accessibility Guidelines' influence on cert; TLOU2 (2020) accessibility; PS5 Cross standardization (2020) and the 25-year Japan/West split; Switch A occupying Xbox's B position; Quake `bind` + `+forward`; vendor IDs 0x045E/0x054C/0x057E; Thrustmaster 0x044F, TWCS product 0xB687; the √2/√3 normalization math; XInput 0-3 connection-order indices; winit backends (Win32/Cocoa/X11/Wayland) and `Ime::Preedit`/`Ime::Commit`; gilrs pairing; UE `ETriggerEvent`, `FGenericPlatformMisc`, `FGenericApplication`, `FViewportClient`, `FGenericWindow`, `UPlayerInput`, `UCommonInputSubsystem`; Unity `Keyboard.current[Key.W].isPressed`, `Mouse.current.delta.ReadValue()`; Godot `DisplayServer`, `_unhandled_input()`, `InputEventKey.unicode`, `InputEvent.device`.

Needs fixing or verification:

1. **`FInputState` (Unreal)**: not a recognizable UE type. Slate processes platform messages, but polled key state lives in `UPlayerInput` (per-key `FKeyState`). Reword.
2. **Cyberpunk 2077 "exposed input latency on PC that console players never noticed"**: weakly supported; CP2077's famous launch problems ran the other way (console performance). Replace with a firmer example or cut.
3. **Elden Ring "displayed Xbox button icons regardless of whether the player was using a controller"**: the canonical Xbox-prompts-for-keyboard case is Sekiro (2019). Elden Ring did ship keyboard glyphs; its complaints were mouse feel and limited rebinding. Verify or reattribute.
4. **"vendor and product IDs (assigned by the USB Implementers Forum)"**: USB-IF assigns vendor IDs; each vendor assigns its own product IDs.
5. **CVAA phrasing**: CVAA mandates accessible *communication* functionality; full remapping as a requirement is XAG/platform-cert territory. Current wording ("accessible input options, including remapping") slightly overclaims the legal requirement; soften.
6. **"normalized to unit length"** for composites: opposing keys (W+S) cancel to a zero vector, which cannot be normalized, and a single key already has magnitude 1. Say "clamped to unit length" or "normalized when magnitude exceeds 1."

## 3. Missing information

1. **Latch semantics** (one paragraph would close all three gaps):
   - Context stack: is "jump" latched during INPUT while a blocking `ui` map sits on top? (It should not be, or a buffered press fires on unpause.)
   - Staleness: a latch set and never consumed (e.g., press on the frame a menu opens) — does it expire, or fire on resume seconds later?
   - Multiple consumers: two systems calling `fixed_action_pressed("jump")` in the same fixed tick — first caller consumes, second sees `false`. Worth stating, since the manual pattern has per-system flags.
2. **Controller connect/disconnect flow**: the listing elides connection events entirely; §Multiple Controllers implies a per-frame rebuild. State the event-driven slot lifecycle (ties into 1.3).
3. **Touch**: Chapter 4's INPUT description promises "every key, button, axis, pointer, and touch point" in the snapshot, and `InputSource::Touch` exists, but `Input` has no touch state and the chapter never scopes touch out. One sentence here (or adjust ch04's phrasing).
4. **Mouse position**: the quarantine listing handles relative motion only; no `CursorMoved` arm, and the elision comment mentions only window events, yet `mouse_position()` is part of the API. Add an arm or a comment.
5. **Key auto-repeat**: OS repeat events are implicitly harmless in this design (setting an already-set bit produces no edge), but the chapter's precision elsewhere earns the one sentence saying so; auto-repeat dedup is only mentioned parenthetically.
6. **Interned names vs. `&str` queries** (observation, spec shares it): `action_held("jump")` must hash the string to find the interned handle on every call, so the "compared in constant time" benefit doesn't apply at the query site. Either acknowledge the per-call hash (fine at these frequencies) or foreshadow a pre-resolved `ActionId`.
7. **Citations**: chapters 1-4 carry 4-10 bibliography citations each; this chapter has zero (the earlier draft's Fiedler citation was dropped in revision). Candidates: Fix Your Timestep (fixed-tick edge section), Game Engine Architecture, CVAA/FCC and XAG primary sources.
